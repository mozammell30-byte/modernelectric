# Free Supabase Setup Guide

This guide explains how to move admin content and uploads away from Render's temporary filesystem, using Supabase's free plan.

## Why This Is Needed

Render can run your Next.js app, but files saved by the app are not reliable long term. If your admin panel saves changes to local files like `data/site-content.json` or uploads images into `public/uploads`, those changes can disappear after a redeploy or restart.

Supabase gives you:

- A free Postgres database for website content.
- Free storage buckets for uploaded images.
- Permanent data that survives Render deploys.

## Create A Supabase Project

1. Go to [https://supabase.com](https://supabase.com).
2. Sign in or create a free account.
3. Click **New project**.
4. Choose an organization.
5. Enter a project name, for example:

```text
modern-electric-website
```

6. Create a database password and save it somewhere safe.
7. Choose the closest region.
8. Click **Create new project**.

Wait until Supabase finishes creating the project.

## Create The Content Table

In Supabase:

1. Go to **Table Editor**.
2. Click **Create a new table**.
3. Use these values on the screen shown in your screenshot.

### Table Settings

| Field | Value |
| --- | --- |
| Name | `site_content` |
| Description | `Stores editable website content` |
| Enable Row Level Security | Keep enabled |
| Enable Realtime | Off |
| Data API Access | On |

### Columns

Keep the default columns:

| Name | Type | Primary |
| --- | --- | --- |
| `id` | `int8` | Yes |
| `created_at` | `timestamptz` | No |

Then add these columns:

| Name | Type | Default Value |
| --- | --- | --- |
| `key` | `text` | empty |
| `content` | `jsonb` | empty |
| `updated_at` | `timestamptz` | `now()` |

Make sure `key` is unique if Supabase shows a unique option. If not, it can be added later with SQL.

Click **Save**.

## Easier SQL Method

Instead of using the table editor manually, you can use SQL.

In Supabase:

1. Go to **SQL Editor**.
2. Click **New query**.
3. Paste this:

```sql
create table if not exists public.site_content (
  id bigint generated by default as identity primary key,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  key text not null unique,
  content jsonb not null
);

alter table public.site_content enable row level security;
```

4. Click **Run**.

## Insert First Content Row

Your app should store all editable website content in one row.

In **SQL Editor**, run:

```sql
insert into public.site_content (key, content)
values ('main', '{}'::jsonb)
on conflict (key) do nothing;
```

Later, the app can replace `{}` with your real website content.

## Create Storage Bucket For Images

In Supabase:

1. Go to **Storage**.
2. Click **New bucket**.
3. Use:

| Field | Value |
| --- | --- |
| Bucket name | `uploads` |
| Public bucket | On |
| File size limit | Optional |
| Allowed MIME types | Optional |

4. Click **Create bucket**.

## Storage Policy

Because images need to show publicly on the website, add a public read policy.

Go to **Storage > Policies**, then add this policy for the `uploads` bucket:

```sql
create policy "Public uploads are readable"
on storage.objects
for select
to public
using (bucket_id = 'uploads');
```

For uploading from your admin API, use the Supabase service role key on the server. Do not expose the service role key in frontend code.

## Get Supabase Keys

In Supabase:

1. Go to **Project Settings**.
2. Go to **API**.
3. Copy these values:

| Supabase Setting | Environment Variable |
| --- | --- |
| Project URL | `SUPABASE_URL` |
| service_role secret key | `SUPABASE_SERVICE_ROLE_KEY` |

## Add Environment Variables Locally

In your `.env` file, add:

```env
SUPABASE_URL=https://your-project-id.supabase.co
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key
SUPABASE_STORAGE_BUCKET=uploads
```

Important:

- `SUPABASE_SERVICE_ROLE_KEY` must only be used in server code or API routes.
- Never commit real secret keys to GitHub.

## Add Environment Variables On Render

In Render:

1. Open your web service.
2. Go to **Environment**.
3. Add the same variables:

```env
SUPABASE_URL=https://your-project-id.supabase.co
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key
SUPABASE_STORAGE_BUCKET=uploads
```

4. Click **Save Changes**.
5. Redeploy your Render service.

## What The App Code Now Uses

The app has been updated to stop using Render's filesystem for admin saves.

- `lib/site-content.ts` reads and writes the `site_content` table.
- `app/api/admin/upload/route.ts` uploads images to the Supabase `uploads` bucket.
- Uploaded images are saved as public Supabase Storage URLs.
- If Supabase has no `site_content` row yet, the app seeds it from `data/site-content.json` once.

## Recommended Free Architecture

Use this setup:

| Need | Free Service |
| --- | --- |
| Website hosting | Render |
| Admin content | Supabase Database |
| Uploaded images | Supabase Storage |

This keeps the project simple and avoids using Render's temporary file storage for important data.

## Final Checklist

- Supabase project created.
- `site_content` table created.
- First row with `key = 'main'` inserted, or let the app seed it automatically on first load.
- `uploads` storage bucket created.
- Public read policy added for uploads.
- Supabase env vars added locally.
- Supabase env vars added on Render.
- App code updated to use Supabase.
- Render service redeployed.
